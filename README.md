# Математически открития

Самостоятелно приложение за състезателна математика за 4. клас. Няма нужда от AI модел или API ключ за уроците.

## Локално ползване

```sh
npm ci
npm run local:start
```

Отвори http://127.0.0.1:3002. Сървърът слуша само на този компютър. `PORT=3003 npm run local:start` сменя порта. `MATHS_DATA_DIR=/private/path` избира друга папка за историята; по подразбиране е `data/`. Съществуващият напредък е пренесен в `data/kids/course-v2.json`, а непроменено резервно копие е в `backups/before-separation/kids/`. Не изтривай тези папки при обновяване.

За локален production build: `npm run build`, после `npm run local:start -- --production`.

## Онлайн режим със Supabase

Тази конфигурация е подготвена, но не е публикувана и не създава автоматично външен проект.

1. Създай отделен Supabase проект и приложи всички файлове от `supabase/migrations/` по реда на имената им чрез SQL Editor или Supabase CLI.
2. Включи Google provider в Supabase Auth. В Google Cloud настрой callback адреса, даден от Supabase. В Supabase URL Configuration задай домейна и разреши точно `https://YOUR-DOMAIN/auth/callback`.
3. Добави одобрените родителски имейли в `allowed_parent_emails` чрез SQL Editor, с малки букви:
   ```sql
   insert into public.allowed_parent_emails(email) values ('parent@example.com');
   ```
4. Задай сървърните променливи от `.env.example`: `MATHS_MODE=hosted`, `MATHS_APP_URL`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. Никога не добавяй `NEXT_PUBLIC_` пред service-role ключа и не го изпращай в браузъра.
5. Изпълни `npm ci`, `npm run build`, `npm start` на избрания хост. Онлайн режимът няма достъп до локалната история и изисква Google вход с одобрен имейл. Създай детски профил с прякор. При един профил приложението го отваря направо; при повече избираш от „Профили“.

Родителският UUID е постоянният Supabase Auth UUID. Всеки детски профил има собствен напредък за всяко състезание. Пилотът допуска най-много пет активни детски профила общо. RLS ограничава видимите профили до родителя; суровият запис на курса не е достъпен през браузърния Supabase API. Командите се проверяват и оценяват на сървъра. Записването използва проверка на ревизията, за да не се презапише по-нов отговор от друг прозорец.

## Пренасяне на история в избрано дете

Първо създай профила след родителски вход. Вземи точните родителски и детски UUID от таблиците. Подготви `.env.local` със Supabase URL и service-role ключ, после:

```sh
npm run progress:import -- --parent-id PARENT_UUID --child-id CHILD_UUID --file /private/path/course-v2.json
```

Командата проверява принадлежността, съвместимостта и прочита записа обратно за проверка. Отказва да презаписва съществуващ напредък. Оригиналният файл остава непроменен. Старите кратки занимания `kids_UUID.json` остават достъпни в локалния архив; текущият курс съдържа цялата текуща история и награди. Материалите и трите Markdown преписа са в `materials/`, извън публичната папка.

## Проверки и структура

`npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.

`bash scripts/test-database.sh` проверява миграциите, правата и едновременното създаване на профили в еднократна локална PostgreSQL 14 база. Не използва реалната Supabase база. При друга инсталация задай `PGBIN`.

Поетапното изпълнение и текущите блокиращи условия са в [plan.md](plan.md); публикуването и възстановяването са описани в [docs/deployment.md](docs/deployment.md), а подготовката на нови състезания - в [docs/content-workflow.md](docs/content-workflow.md).

- `src/core/`: детерминирана учебна логика; не извиква външен модел.
- `src/server/`: подготвени задачи, решения, проверка на достъпа и команди.
- `src/store/`: локален файлов адаптер и асинхронен Supabase адаптер.
- `components/`, `app/`: самостоятелният детски интерфейс.
- `key-decisions.md`: образователни решения.
- `materials/`: частни източници; `public/kids/`: само използваните чертежи и илюстрации.

Не публикувай `data/`, `backups/`, `.env*` или `materials/` като статични файлове. Те са изключени от Git и от server bundle tracing. Условията на AGPL и произходът на използвания код са в `LICENSE` и `NOTICE`.
